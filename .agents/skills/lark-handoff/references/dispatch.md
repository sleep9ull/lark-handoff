# 主 Agent 调度与单任务执行

## 主 Agent

1. 按技能入口完成预检、持有清单锁并恢复待回写审计后，以任务 GUID 去重候选，读取全部评论、解析项目和前置依赖。项目无法确定的任务由主 Agent 按失败规则审计，不派发代码工作。仍有待恢复事件的任务 GUID 本轮不派发新工作，保留原 journal 和 event_id，报告恢复缺口。
2. 在运行目录维护 `dispatch.json`，用临时文件加原子替换保存 run_id、每项任务的 GUID、项目真实路径、规范化远端仓库身份、预留分支名、排队/派发中/运行/结束状态、sub-agent 标识及停止情况。仅主 Agent 写此文件；按 contract.md 检查并预留分支名后，创建执行者前先记派发意图，返回后记录其标识。派发结果不确定时先查现有执行者，不盲目重试。
3. 使用 Codex 原生 sub-agent 工具，每次分配一个飞书任务；使用当前环境的可用并发额度，保留主 Agent 的调度能力，超额任务排队。执行者结束后可复用，但下一次分配仍只有一个任务。sub-agent 不再委派，也不创建独立 Codex 任务或调度。工具不可用时报告能力缺失，不宣称已并行执行。
4. 派发时传入：本技能及引用文档的绝对路径、清单和任务 GUID、共享 run_id、运行目录及 journal 路径、「所属项目」字段 GUID、原始值与解析名称、已验证项目/远端、观察到的状态、任务与评论摘要、前置依赖、预留或恢复的分支名、已有 PR/验收 SHA（如有）。明确执行者只拥有本任务的 journal、评论、状态、分支和工作树写入权；摘要用于定位，实际执行仍须复读飞书和远端事实。
5. 等待执行者完成，处理其资源请求和全局阻塞，及时补充派发符合条件的排队任务。逐项核对返回证据和 journal、评论、状态回读结果；有缺失时在原执行者停止后接管恢复，不重复已完成的 Git 或 PR 操作。
6. 全部执行者及关联进程停止、每项结果已核对或明确保存待恢复事项后，释放本轮清单锁，汇报结果与需要人工处理的问题。

## 并发边界

- 自动生成的新分支重名按 contract.md 分配后缀；派发前核对现有或明确约定的分支、PR 和 worktree 归属；不同任务指向同一远端分支、PR 或真实 worktree 时，报告冲突并停止相关派发。执行者复读后发现归属变化也须停止并报告，不覆盖其他任务成果。
- 同一任务 GUID 同时只有一个执行者。主 Agent 在派发后仅读取该任务 journal；确认执行者及其进程停止后才能接管写入或重新分配。恢复审计在派发之前完成。
- 无前置依赖的开发任务可并行，包括同项目中使用独立分支/worktree 的任务。明确依赖尚未满足时按契约进入 `need-to-refine`；不会因为前置任务已交付待验收就视为依赖已满足。
- 同一远端仓库的 `ready-to-merge` 任务从首次 Fetch 到最终远端验证与回写均串行；不同本地路径或远端 URL 写法若指向同一仓库，也归入同一合并队列。不同仓库可并行合并。后续合并重新读取最新 main、任务和批准 SHA；冲突仍按执行流程交还人类。
- worktree 共享 Git 元数据。同一 Git common directory 下的 Fetch、分支/worktree 创建或清理等共享写入，sub-agent 须先向主 Agent 申请执行时段，获准后操作、完成后报告释放；主 Agent 同时只批准一个。各自 worktree 内的编辑、测试、提交和独立分支推送可并行。
- 测试或开发服务器使用独立端口和输出目录；无法隔离的共享数据库、固定端口等资源由主 Agent 串行安排相关步骤。执行者等待批准时不抢占或清理其他任务资源。

## sub-agent 收尾与异常

执行者按 execution.md 完成单项工作及 audit.md 回写，返回任务 GUID、实际状态、分支/worktree、PR、交付或合并 SHA、验证证据、journal 路径、待恢复事项，以及自己启动的进程是否已停止。单项失败保存证据并返回，其他独立任务继续。

发现全局身份、权限或状态配置问题时，执行者立即保存现场并通知主 Agent。主 Agent 停止派发，通知所有执行者停止新副作用并保存当前事实；已在途的操作先核实结果。必要时中断执行者，但中断返回不等于关联 Git/测试进程已退出，须检查后才能回收资源或释放锁。

主 Agent 或 sub-agent 意外结束时，结合 dispatch.json、journal、实际执行者和进程状态恢复。无法证明旧执行者已停止时保留清单锁及该任务写入归属，报告需人工确认；超时或缺少回复不能作为重新派发的依据。
